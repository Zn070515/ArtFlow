# ADR-0005: 测试金字塔 + golden fixtures + property tests

状态：proposed（2026-10-19）

## 背景

v1 有 2300+ 测试，但仍有大量问题在评审轮才被发现；这些问题集中在权限闭包、
状态机、并发和“同一事实多个来源”。v2 需要在实现前就把规则写成可执行契约。

## 决策

- **领域单元测试**：纯函数命令与编译器；快速、无数据库。
- **属性测试**（fast-check）：不变量对随机输入成立，例如“release 后不可再编辑”
  “计划 hash 与文档一致才能 release”“第二个 running run 必被拒”。
- **Golden fixtures**：`tests/golden/*.json` 是实现无关的业务样例；v1 适配器
  和 v2 runner 消费同一份文件。
- **Contract tests**：模块间 contract、HTTP 错误码、OpenAPI 响应。
- **并发测试**：真实 PostgreSQL + 双连接，固定 interleaving。
- **E2E**：只覆盖关键现场旅程（扫码、录分、发布、纠错），不做全页面回归。
- **结构门禁**：`tests/gates/` 持续检查清单、权限闭包、部署产物。

## 后果

- 每个新不变量必须同时有：领域描述、反例测试、Golden（如适用）。
- 测试运行时间需要分层：单元秒级，集成分钟级，E2E 只在关键路径。
- golden fixture 需要版本化；变更期望必须说明是规则变了还是实现变了。

## 替代方案

- **只写 E2E**：慢、脆弱，且无法覆盖并发/属性边界，否决。
- **只写单元测试**：无法证明跨模块/部署一致性，否决。
