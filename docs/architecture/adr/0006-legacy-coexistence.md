# ADR-0006: Strangler 共存与按切片 cutover

状态：proposed（2026-10-19）

## 背景

v1.0.0 是 2026 院十佳的 production baseline，必须保持可部署；v2 不能一次性
替换所有功能。历史数据和真实业务流程是 v2 的参照。

## 决策

- v1 保持在 `main`（1.x），只接受现场/生产修复；v2 在 `artflow-plus` 开发。
- v2 按 **vertical slice** 交付：每条切片包含领域、API、页面、迁移与 golden。
- 新切片先在 v2 自测与 golden 对上，再在隔离环境与 v1 并行验证；通过后切换
  入口，v1 保留只读回退窗口。
- 数据边界：同一时刻只有一侧拥有某张表的写权；禁止双写同一事实。
- 事件/导出用于迁移校验；历史数据通过可重放的导入命令进入 v2。
- 修复传播：实现 bug 只修 v1；业务不变量同步到 `docs/invariants` 与 golden。

## 后果

- 需要维护两套运行环境与数据迁移脚本；
- 每次 cutover 都要有回滚开关和验证报告；
- v1 的 Django 代码最终删除前，必须先证明没有入口指向它。

## 替代方案

- **一次性重写并切换**：风险不可控，且会丢失 v1 的行为参照，否决。
- **长期双写**：会产生两个事实源，否决。
