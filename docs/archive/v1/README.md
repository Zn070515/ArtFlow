## 1. 产品定位与角色

ArtFlow 1.x 是面向学院文艺部的活动管理平台，覆盖两类活动：

- 歌手比赛（十佳歌手）：报名、问卷、材料、赛制、评委评分、观众投票、结果公示、归档
- 毕业晚会：节目征集、节目材料、节目审核与节目单

角色：

| 角色 | 主要入口 | 能做什么 |
| --- | --- | --- |
| 选手/参与者 | 公开报名页、`/me/` | 报名、填问卷、上传材料、补交、查看结果 |
| 评委 | `/judge/terminal/`、一次性席位链接 | 认领席位、看当前选手、打分 |
| 工作人员 | `/staff/` | 活动、报名、材料、赛制、评分、投票、票据、结果、导出、归档 |
| 管理员 | `/staff/`、Django admin（非生产） | 全部运营操作、账号与权限、冻结/解锁、审计 |
| 观众 | 投票页、结果页 | 凭票据或浏览器会话投票、查看公示 |

## 2. 功能面

### 公开门户

- 首页、公告、往届风采、结果公示、隐私页
- 活动入口 `/e/<public_code>/`：报名、Live 状态、评委入口
- 结果公示包含冻结快照、奖项与撤销/再发布状态

### 报名与问卷

- 活动报名：草稿、提交、审核、名单最终化（FINAL/UNKNOWN）
- 问卷 DSL：版本化 schema、题目类型、文件槽位、自动保存、提交
- 分组问卷：按组填写、组材料窗口、组问卷预览与构建器
- 2026 现场赛问卷与规则集模板的升级命令

### 材料

- 材料槽位（按题目/组/节目）、上传、替换、审核、补交
- 材料检查（缺交/已交/需补交）、来源规则集版本
- 受控媒体访问：按所有权/工作人员/公开标记判定，不暴露私有媒体静态路径

### 赛制、评分与结果

- 规则集模板、版本化规则图、编译器/验证器、冻结与绑定
- 轮次、评委组、席位、表演、评分事实、纠错、排名、晋级
- 快速录分、代录、纸质抄录、评委一次性席位与命令回执
- 观众评分、复合分、踢馆/挑战赛、手动决策、同分裁决
- 结果候选 → 核定 → 发布 → 撤销/再发布；结果与规则集版本绑定

### 投票与票据

- 观众投票场次（单选/多选）、票据要求、浏览器身份、投票唯一性
- 票据签发、轮换、撤销、入场会话、签到
- 投票结果统计、导出与公示

### 导出与归档

- Excel 导出：报名、评分模板、成绩、投票结果
- Word/微信推文模板与生成文档
- 二维码：报名、投票、结果入口
- 归档包：文件清单、冻结标题、结果闭合校验、受控下载
- 审计日志、异常事件记录、测试数据保护与清理

### 运营后台

- 活动创建/克隆/锁定/解锁/归档
- 报名审核、名单、材料、赛制、轮次、评委、评分、投票、票据、结果、导出、归档
- 账号、角色、密码、维护模式、会话失效、备份与诊断命令

## 3. 模块与数据

1.x 是 Django monolith，17 个业务 app：

| app | 职责 |
| --- | --- |
| `accounts` | 自定义 User、角色、登录/注册/资料 |
| `core` | Activity（活动类型、阶段、锁定、公开码、评委入口版本） |
| `common` | 审计、限流、维护模式、种子记录、通用命令 |
| `public_portal` | 公开文章、结果发布、公开媒体 |
| `files` | 提交文件、材料要求、材料检查、材料槽位、工作人员备注 |
| `ruleset` | 规则集模板/版本、编译、绑定、规划草稿 |
| `questionnaire` | 问卷响应、schema、组问卷 |
| `singer_contest` | 歌手报名、分组、轮次、评委、表演、评分、挑战赛、结果 |
| `farewell_show` | 毕晚节目报名与排序 |
| `voting` | 投票场次、选项、选票、计分规则 |
| `tickets` | 票据、入场会话、签到 |
| `entry_access` | 入场点、访问授权、临时会话 |
| `exports` | 导出任务、文章模板、生成文档 |
| `archive` | 归档包 |
| `incidents` | 异常事件记录 |
| `staff_panel` | 工作人员/管理员操作视图 |
| `realtime` | Channels WebSocket 通知（只做提示，不承载权威） |

完整模型、管理命令与 URL 清单见 [`inventory.md`](inventory.md)。

## 4. 关键不变量（v1 证据）

- 活动是变更边界：写操作先取 Activity 行锁，再服从活动/轮次/投票锁定
- 权限先于 mutation；模板不是授权边界
- 已核定结果不可改写；修正走新版本
- 私有文件只经受控媒体视图访问
- 测试/彩排数据与正式数据隔离，离开测试模式前清零
- 敏感操作、导出、解锁全部留审计
- 评分/投票/票据唯一性与并发由数据库约束 + 命令回执保证

这些规则已提炼为 v2 的 `docs/invariants/`、`docs/domains/`、`tests/golden/`。

## 5. 与 v2 的关系

- v2 不是 v1 的逐行移植；capability + Pack 重新实现同一业务事实
- v1 数据**不迁入** v2；v1 数据随源码归档
- v1 的 legacy 导入/adoption、参与者认领、媒体桥与 cutover 已删除
- v2 仍缺的 v1 功能（公开公告/往届风采、舞台节目单、XLSX/Word 导出、
  bracket、现场大屏、SSO、多实例实时）记录在覆盖审计中
