# M15.4 Schedule / Program Release 设计（2026-11-14）

## 0. 状态

Implemented and merged (2026-11-14) through PR #98, together with Studio
Professional Mode. 运行期细节见 [`docs/domains/schedule.md`](../../../domains/schedule.md)。

## 1. 背景

舞台类活动在 v2 里只有“报名/材料/归档”，没有排期权威：

- 公开节目单只是已审核报名的投影，不能表达节目顺序、槽位、时长；
- Ops 不能调整顺序、处理迟到/换序；
- Live 没有“当前/下一位节目”；
- 发布只存在于比赛结果发布，没有节目单版本。

M15.4 新增 `schedule` capability，把“排期定义、节目条目、公开节目单版本、
现场当前进度”做成独立领域事实。

## 2. 领域模型

### 定义（Studio）

```ts
ScheduleDefinition {
  schemaVersion: 1;
  version: string;
  slots: { key; label; durationMinutes; kind: "program"|"break"|"ceremony" }[];
}
```

编译产物：

```ts
CompiledScheduleArtifact {
  version: 1; schemaVersion: 1;
  slots: [...];
}
```

`createEmptyScheduleDefinition()` 可编译（空槽位），由 Pack 或 Studio 填充。

### 运行时事实（Ops / Live）

| 表 | 作用 |
| --- | --- |
| `schedule_state` | `(activity_id, mode)` 的单调 revision，所有写命令的 OCC 锚点 |
| `schedule_entry` | 有序节目条目：position、slot_key、participant_id、title、note、revision |
| `schedule_release` | 不可变公开快照：version、snapshot jsonb、released_at、revoked_at |
| `schedule_current` | 运行中会话的当前条目指针 |

`mode` 覆盖 `test | rehearsal | formal`；公开只读取 **formal** 的最新未撤销 release。

### 命令

- `schedule.entry.upsert` — 添加/编辑条目，带 `expectedRevision`；
- `schedule.entry.reorder` — 校验 orderedIds 是当前集合的精确排列；
- `schedule.entry.remove`；
- `schedule.release` — 冻结当前顺序，version 自增；
- `schedule.release.revoke` — 撤销某一版；
- `schedule.current.advance` — 绑定运行中的 `schedule` execution session，
  mode 从 session 读取，不接受客户端指定。

所有命令走 `executeCommand`：receipt + audit + fact + outbox 同一事务；
`schedule.manage` 授权；`schedule_state.revision` 做 OCC；旧版本返回
`STALE_REVISION`。

### 读面

- Ops：`GET /api/activities/:id/schedule?mode=...`，access `schedule`；
- 公开：`GET /api/public/schedule/:publicCode`，只返回 formal active release；
- 公开节目单页 `/program/:publicCode` 优先读取 schedule release，没有 release 时
  回退到已审核报名（兼容旧活动）。

## 3. 产品面

| 面 | 交付 |
| --- | --- |
| Studio | `ScheduleEditor`：槽位 key/label/时长/类型；随 Definition 编译/发布 |
| Ops | `ScheduleCard`：模式切换、添加/上移/下移/删除、发布/撤销、启动/关闭排期会话、下一位 |
| Live | `ScheduleSummary`：当前/下一位、下一位操作 |
| Portal | 公开节目单页显示 release 的顺序、槽位、标题、备注 |

Stage Show Pack 默认启用 `schedule`，并提供开场/节目/谢幕三个槽位。

## Test architecture

**Contracts and capabilities touched**

新增 `schedule` capability（manifest、compiler、empty definition、registry、stage-show pack）。
新增 `packages/db/src/schedule-repository.ts`、`0025_schedule` migration、
`runtime/schedule-service.ts`、`api/routes/schedule.ts`、Web `api/schedule.ts` 与
`ScheduleCard`/`ScheduleSummary`/`ScheduleEditor`。没有修改既有 capability 的语义。

**Consumers and read models**

- Ops `ScheduleCard`、Live `ScheduleSummary`、公开 `/program` 页；
- Consumer Graph：6 条 mutation route 由 Web client 消费；5 个 schedule 事件在
  `dynamic-dependencies.json` 声明为 Ops 读模型的消费边。
- `graph:check` 零未解析边；`audit:check` 无新增 gap。

**Lifecycle, terminal guards, and mode isolation**

- 每条写命令先校验 activity active，再按 `(activity, mode)` 锁 `schedule_state`；
- `expectedRevision` 不匹配 → `STALE_REVISION`；
- release 是 append-only 版本；撤销只设置 `revoked_at`，不改写旧快照；
- 公开只读 formal 且未撤销的最新版本；
- `schedule.current.advance` 必须来自运行中的 `schedule` session，mode 由 session
  决定，防止 test/rehearsal 污染 formal。

**Adapters**

不新增 contract-tools lifecycle adapter：schedule 是有序条目 + 发布快照，不是单状态
生命周期；在 `adapter-coverage.test.ts` 以具体理由豁免。运行时测试使用真实
PostgreSQL 和真实 command path，不 mock 仓储。

**Fault and recovery cases**

- stale `expectedRevision`（两次并发写只有一个成功）；
- orderedIds 缺项/重复/含其他活动条目 → `INVALID_INPUT`；
- 未启用 schedule 的 release → `SCHEDULE_NOT_ENABLED`；
- 未知槽位 → `SLOT_UNKNOWN`；
- 空排期发布 → `SCHEDULE_EMPTY`；
- 未运行 schedule session 时 advance → `SESSION_NOT_RUNNING`；
- 撤销后公开 selector 不再返回该版本；
- 重新发布生成新 version，旧版本仍可审计。

**Why existing tests are insufficient**

原有 stage-show 只覆盖报名/材料/归档；公开节目单只是报名投影。没有测试能证明
顺序、OCC、发布快照和 mode 隔离。

**Anti-bloat decision**

复用 `executeCommand`、receipt/audit/outbox、`getRelease`/`requireRunningCommandSession`
和现有 public program 页；不新增第二套发布框架、不复制 command 路径。`schedule`
的四张表与一个 repository 足以表达当前语义；Live 只做只读摘要 + advance。

**Focused gates**

`pnpm -C plus --filter @artflow-plus/domain test schedule`、
`pnpm -C plus --filter @artflow-plus/runtime test schedule-service`、
`pnpm -C plus --filter @artflow-plus/api test`、
`pnpm -C plus --filter @artflow-plus/web test`、
`pnpm -C plus run schema:check`、`graph:check`、`audit:check`、
`uv run pytest tests/gates -q`、Playwright `e2e/schedule.spec.ts`。
