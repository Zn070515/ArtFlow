# ArtFlow-Plus 产品目标（v2.0）

状态：规划基线（2026-10-19）。v1 的 GOAL 仍是生产实现的规范；本文只定义 v2 的
目标和边界。

## 一句话

为同一个院系活动运营场景，重写一套**可证明正确、可长期演进**的活动与竞赛
平台：规则先编译、执行可重放、正式结果只有一个权威、事故知识留在系统里。

## 用户与核心旅程

| 角色 | 核心旅程 |
| --- | --- |
| 选手 | 注册/登录 → 填问卷与材料 → 查看轮次与结果 |
| 评委 | 扫码认领席位 → 对当前表演打分 → 看到自己的提交状态 |
| 工作人员 | 配置活动与赛制 → 审核报名 → 现场控制 → 录分/纠错 |
| 管理员 | 冻结赛制、核定结果、发布/撤销公示、归档 |
| 观众 | 查看 Live 进度 → 凭票投票（如启用） |

## v2.0 范围

- 活动生命周期、角色与权限。
- 赛制定义（DSL）→ 校验 → 冻结 → 发布版本。
- 报名、问卷、材料与审核。
- 轮次、评委组、表演、评分事实、纠错。
- 投票、票据与观众成绩组成。
- 结果候选 → 核定 → 公示快照 → 撤销/再发布 → 归档。
- 媒体受控访问、导出与备份恢复。
- 实时协作与现场降级（HTTP 轮询可兜底）。

## 明确不在 v2.0

- 多租户 SaaS、计费、开放注册的第三方生态。
- 原生移动 App（Web 优先，手机浏览器是现场主入口）。
- 支付、票务销售、人脸识别。
- 依赖某一家云厂商的专有能力；部署必须能在单机/校内服务器完成。
- 把 v1 的所有历史实现原样搬运；只保留业务事实、Golden 和不变量。

## 成功标准

1. **行为对齐**：核心链的 golden fixtures 在 v2 上全部通过；同一输入产生同一
   领域事件/拒绝码。
2. **可证明**：每条不变量有反例测试；结构门禁在 CI 常绿。
3. **可运维**：单来源部署、不可变版本、静态产物与镜像同版、备份可恢复。
4. **可演进**：领域模块不共享表；新增活动类型/节点类型不需要改核心内核。
5. **可迁移**：按 vertical slice 从 v1 切换，任一步都能回退；v1 保持可部署
   直到 cutover 完成。

## 约束

- 中文界面、手机优先；现场网络可能不稳定。
- PostgreSQL 是事实源；不得依赖 Redis 才能正确。
- 身份认证可插拔；默认本地账号，学校 SSO 作为适配器。
- 不允许“为了赶时间”的隐式规则：所有权威转换必须显式、可审计、可重放。
