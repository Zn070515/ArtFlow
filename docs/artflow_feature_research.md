# ArtFlow 功能研究与后续路线

更新日期：2026-07-06

## 1. 本轮验收记录

人工 review 后确认，上一轮锁定、审计、文件访问、测试模式清理、导出归档、动态活动等核心缺口已经基本补齐，并通过全量 Django 测试。

本轮 review 发现并修复了一个投票链路的稳定性问题：

- `vote_cast` 原先通过 `request.session.session_key or request.session.create()` 获取会话 key，Django 的 `create()` 不返回 key，极端情况下可能写入空浏览器会话标识。
- 投票短时限流原先直接读取 `REMOTE_ADDR`，部署在反向代理后可能拿不到真实客户端 IP。

修复提交：

```text
415f1c9 fix: harden vote casting identity tracking
```

验证命令：

```bash
rtk python manage.py check
rtk python manage.py makemigrations --check --dry-run
rtk python manage.py test
```

结果：全部通过，24 个测试 OK。

## 2. 第一轮外部调研结论

参考校园参与平台、活动管理平台、奖项评审平台的公开资料后，ArtFlow 后续不应只补单点功能，而应向“文艺部活动运营系统”发展。重点方向包括：

- 组织性：排期、任务分工、岗位表、彩排节点、物资清单。
- 功能性：二维码签到、节目单、投票、评分、获奖、公示、归档闭环。
- 知名度：公开活动主页、分享卡片、照片墙、获奖展示、年度回顾。
- 数据沉淀：报名趋势、到场率、投票量、参与画像、部门工作量。
- 风险控制：锁定、审计、权限、受控文件访问、正式数据保护。

## 3. 初步功能建议

### 3.1 活动运营排期板

为每个活动提供内部排期板，记录负责人、任务、截止时间、状态、备注。适合管理报名截止、节目审核、彩排、物资准备、现场岗位、推文发布时间等节点。

### 3.2 二维码签到与到场分析

每个活动生成签到码，现场扫码签到。系统按班级、年级、学院、活动类型统计到场情况，供复盘和对外宣传使用。

### 3.3 公开活动主页与分享卡片

活动自动生成公开页，包含简介、报名入口、节目单、投票入口、获奖结果、精彩照片和附件下载。系统生成适合微信、QQ 空间、公众号封面的分享图。

### 3.4 多轮评审与大众投票组合

支持初筛、复赛、决赛、评委评分、大众投票、人气奖、公示锁定等组合流程，使歌手比赛、毕晚节目、主持人征集等活动都能复用同一套流程骨架。

### 3.5 数据驾驶舱

提供活动数、报名数、审核通过率、到场率、投票数、作品数、热门活动、部门任务量、历史趋势等指标。目标是让文艺部能用数据复盘，而不是只靠口头经验交接。

### 3.6 宣传内容流水线

从活动数据一键生成获奖名单页、公众号初稿、节目单 PDF、照片墙、年度活动档案页，减少重复整理材料的工作量。

### 3.7 成员与选手成长档案

记录学生参加过的节目、比赛、获奖、志愿服务、主持、摄影、后勤等经历，逐步沉淀校园艺术人才库。

### 3.8 活动反馈与复盘

活动结束后自动收集观众、选手、工作人员反馈，并沉淀为复盘记录：满意度、问题、建议、下次改进项。

## 4. 第二轮调研待补充

已继续深入检索以下方向：

- 校园组织管理与学生参与平台的成熟功能。
- 艺术节、演出、比赛、奖项系统的评审与宣传功能。
- 二维码签到、入场核验、现场大屏、反馈问卷、志愿者管理。
- 高校社团/学生组织提升影响力的线上运营做法。
- 适合 ArtFlow 当前 Django 架构的分阶段落地路线。

## 5. 第二轮深入调研结论

### 5.1 成熟校园参与平台的共同特征

CampusGroups、Modern Campus Involve、Anthology Engage、Presence 等平台都不是单纯的报名系统，而是围绕学生组织运作建立统一入口。共同能力包括：

- 组织主页、成员名册、角色权限、文档管理。
- 活动创建、审批、RSVP、签到、出席统计、导出。
- 校园活动日历和移动端入口，让学生更容易发现活动。
- 选举、投票、表单、财务或资源申请等组织治理能力。
- 参与记录、能力证明、徽章、积分、共同课程记录等长期画像。
- 后台分析，用于判断活动覆盖面、参与趋势、组织活跃度。

对 ArtFlow 的启发：文艺部不需要做完整学生事务平台，但应吸收“组织、活动、参与、传播、数据”这五个骨架。现有的 `Activity`、报名、评分、投票、归档模型已经有基础，下一步应补“组织运营层”和“参与数据层”。

### 5.2 艺术比赛与奖项系统的共同特征

Evalato、Judgify、Award Force、Submit.com、Zealous 等奖项/比赛平台强调：

- 自定义报名/投稿表单。
- 参赛者门户，能修改资料、补交附件、查看状态。
- 评委分配、评分表、盲评、多轮评审、入围名单。
- 公开投票、观众选择奖、结果报表。
- 自动邮件/通知，减少人工催材料。
- 品牌化活动页面和报告分析。

对 ArtFlow 的启发：歌手比赛只是一个特例，系统应抽象为“征集 -> 审核 -> 评审 -> 公示 -> 传播 -> 归档”。毕晚节目、主持人征集、摄影作品征集、校园艺术作品展都可以共用这条主链路。

### 5.3 演出和现场活动系统的共同特征

演出/会务/活动工具普遍覆盖：

- 报名或票务、电子票、二维码核销。
- 现场签到、离线扫码、入场统计。
- 节目单、议程、座位、场地、设备、制作资源管理。
- 现场大屏、实时投票、互动问答、抽奖、反馈。
- 活动后数据导出和复盘。

对 ArtFlow 的启发：文艺部活动不一定需要商业票务，但非常需要“电子入场凭证 + 签到核销 + 现场大屏 + 节目单 + 复盘数据”。这些功能能明显提升现场秩序和专业感。

### 5.4 国内活动工具的共同特征

腾讯问卷、草料二维码、百格活动、准到、会腾等国内工具强调低门槛传播和微信场景：

- 二维码作为入口，连接报名、签到、核销、资料领取。
- 自定义表单、报名审核、报名后自动生成凭证。
- 微信内分享、公众号菜单、小程序入口、活动海报。
- 实时统计、Excel/PDF 导出、现场大屏互动。
- 活码内容可更新，避免海报印刷后链接失效。

对 ArtFlow 的启发：如果面向校内真实使用，公开活动页和二维码中心要优先适配微信扫码传播。短期可以先用 Web 页面和普通二维码，不必立即开发小程序；中期再考虑微信生态集成。

### 5.5 大学活动规划、风险与无障碍要求

多所大学的学生组织活动指南都强调：

- 活动目的、时间、地点、预算、宣传、人员、设备需要提前确认。
- 场地、雨天预案、AV 设备、餐饮、志愿者、现场流程都应进入清单。
- RSVP/报名表应收集无障碍需求。
- 场地应考虑轮椅通行、无障碍卫生间、听力辅助、字幕、照明、导览。
- 高风险活动需要风险评估、审批和事故预案。

对 ArtFlow 的启发：系统不应只追求报名投票，还要帮助学生干部“少漏项”。可以引入活动检查清单、风险等级、无障碍需求字段、应急联系人和现场预案模板。

## 6. 建议新增的功能模块

### 6.1 活动生命周期模板

为不同活动类型建立流程模板：

- 歌手比赛：报名 -> 材料审核 -> 初赛 -> 复赛 -> 决赛 -> 人气投票 -> 获奖公示 -> 归档。
- 毕晚节目：节目征集 -> 节目初审 -> 彩排 -> 节目单确认 -> 现场演出 -> 照片/视频归档。
- 普通征集：报名 -> 审核 -> 名单确认 -> 结果发布 -> 资料归档。
- 展示活动：作品征集 -> 审核 -> 展示页发布 -> 观众互动 -> 年度归档。

落地方式：在 `Activity` 上增加活动模板概念，自动生成阶段、任务清单、材料要求、默认导出项。

### 6.2 内部任务与岗位管理

新增文艺部内部工作台：

- 任务看板：待办、进行中、待确认、完成。
- 负责人、协作者、截止时间、优先级、关联活动阶段。
- 现场岗位表：主持、控场、音响、灯光、签到、摄影、催场、统分。
- 交接备注：每个岗位保留注意事项和复盘。

价值：减少口头安排，降低换届后的接手成本。

### 6.3 活动审批、风险和无障碍清单

为活动增加上线前检查：

- 场地是否确认。
- AV/灯光/麦克风/伴奏是否确认。
- 雨天或备用场地是否确认。
- 是否需要志愿者、安保、医药箱。
- 报名表是否收集特殊需求。
- 公示内容是否经过复核。
- 文件权限、投票时间、评分锁定是否正确。

价值：把“经验型提醒”固化成系统流程。

### 6.4 二维码中心升级

现有二维码能力可继续扩展：

- 报名二维码。
- 签到二维码。
- 工作人员核销二维码。
- 投票二维码。
- 公示二维码。
- 节目单二维码。
- 活动主页二维码。
- 归档包内部索引二维码。

每个二维码应有用途、有效期、访问权限、扫描统计和停用状态。

### 6.5 签到与入场核验

新增 `CheckInSession` / `CheckInRecord` 类能力：

- 报名成功后生成个人入场码。
- 工作人员扫码核销。
- 支持现场手动补签。
- 支持签到名单导出。
- 支持到场率、迟到率、未到名单统计。
- 支持观众签到、选手签到、工作人员签到三类。

短期只做在线扫码；中期再考虑离线缓存。

### 6.6 现场大屏与控场视图

为现场执行提供专门视图：

- 当前节目、下一节目、候场名单。
- 实时投票数、签到人数、评分进度。
- 获奖名单公布模式。
- 抽奖或互动投票。
- 控场员只看必要信息，不暴露后台管理入口。

价值：提升现场专业感，也减少主持、催场、统分之间的信息断层。

### 6.7 评审工作台升级

在现有评分基础上扩展：

- 评委分配到具体轮次、组别、节目。
- 评分表模板：音准、台风、感染力、完整度等。
- 盲评模式：隐藏选手姓名或班级。
- 评委未完成提醒。
- 异常分检测：过高、过低、漏评。
- 评分锁定后生成不可变快照。

价值：让比赛结果更可解释，也方便事后追溯。

### 6.8 公开传播矩阵

公开端不只展示结果，还应承担宣传：

- 活动日历。
- 活动专题页。
- 节目单页。
- 选手/节目展示卡。
- 精彩照片墙。
- 历届获奖墙。
- 年度文艺回顾页。
- 一键生成公众号初稿和分享海报。

价值：把系统从内部工具扩展为文艺部的品牌阵地。

### 6.9 通知与提醒

新增轻量通知：

- 报名成功提醒。
- 审核通过/驳回提醒。
- 补交材料提醒。
- 彩排时间提醒。
- 投票开启/关闭提醒。
- 评委未评分提醒。
- 活动发布和公示提醒。

短期可站内通知 + 管理后台导出通知名单；后续再考虑企业微信、邮箱、公众号模板消息。

### 6.10 复盘与数据驾驶舱

每个活动结束后生成复盘页：

- 报名数、通过数、签到数、到场率。
- 投票数、访问量、分享点击量。
- 各阶段耗时、材料缺失率、审核驳回原因。
- 现场问题记录。
- 观众/选手/工作人员反馈。
- 下次活动建议。

部门总览页展示年度趋势、热门活动、最活跃成员、活动覆盖面。

### 6.11 人才库与共同参与记录

建立面向文艺部的人才沉淀：

- 选手档案：参赛、节目、获奖、作品。
- 工作人员档案：主持、摄影、音响、灯光、策划、后勤。
- 标签：声乐、舞蹈、器乐、主持、摄影、剪辑、文案。
- 可按活动经验筛选适合人选。

价值：换届后仍能知道“谁能唱、谁会主持、谁做过控场”。

### 6.12 文件与素材资产库

在受控文件访问基础上扩展：

- 活动海报、推文图、节目照片、视频、伴奏、报名附件统一入库。
- 素材按活动、类型、可公开状态、作者、授权状态分类。
- 公示/公众号使用过的素材可回溯来源。
- 支持生成附件索引和归档索引。

价值：解决照片、伴奏、文件散落在聊天记录里的问题。

## 7. 分阶段落地路线

### Phase 2：组织性增强

优先实现：

- 活动生命周期模板。
- 内部任务看板。
- 活动检查清单。
- 二维码中心持久化。
- 签到与入场核验。

验收标准：一个活动从立项到现场执行，负责人、节点、二维码、签到数据都能在系统里闭环。

### Phase 3：现场执行增强

优先实现：

- 现场大屏。
- 控场视图。
- 评审工作台升级。
- 评委提醒和异常分检测。
- 现场问题记录。

验收标准：歌手比赛和毕晚现场不再依赖多个 Excel、群消息和临时纸质表。

### Phase 4：传播与知名度增强

优先实现：

- 活动专题页。
- 分享海报生成。
- 历届活动/获奖墙。
- 照片墙。
- 公众号初稿生成。

验收标准：每场活动结束后能快速生成对外展示内容，文艺部有持续可访问的公开作品集。

### Phase 5：数据与传承增强

优先实现：

- 年度数据驾驶舱。
- 活动复盘报告。
- 人才库。
- 素材资产库。
- 换届交接包。

验收标准：新一届成员可以通过系统理解上一届活动规模、流程、素材、问题和可复用经验。

## 8. 对当前代码架构的建议

### 8.1 不要把所有新能力塞进 `staff_panel`

`staff_panel` 已经承担很多流程入口。后续建议按领域拆分：

- `operations/`：任务、岗位、检查清单、排期。
- `checkins/`：签到场次、签到记录、核销。
- `analytics/`：数据驾驶舱、复盘报告。
- `showcase/` 或继续增强 `public_portal/`：公开专题、照片墙、获奖墙。

### 8.2 继续坚持统一锁定和审计

新增所有会修改业务结果的操作都必须接入：

- 活动锁定检查。
- 阶段/结果锁定检查。
- 管理员解锁流程。
- 审计日志。
- 回归测试。

尤其是签到补录、评分修改、获奖发布、公开内容发布、素材公开状态修改。

### 8.3 先做 Web，不急着做小程序

国内调研显示微信入口重要，但 ArtFlow 当前更适合先做好：

- 移动端友好的 Django 模板页面。
- 普通二维码。
- 微信内可打开的公开页。
- 分享标题、封面图、摘要。

等真实活动跑通后，再考虑小程序或公众号深度集成。
