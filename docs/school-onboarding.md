# 学校接入准备清单

本文档是接入前的责任与证据清单，不是合规认证，也不替学校或部署方决定身份提供商、保存期限或公网防护方案。每次活动都应把以下字段填入活动档案：责任人、用途、分类、学校批准的保存期限、导出授权人、删除/法律保全责任人、证据位置。

## 数据清单

| 数据族 | 最小用途与分类 | 接入前必须确认的责任与证据 |
| --- | --- | --- |
| 学生/报名 | 报名、节目、资格核验；学生个人信息 | 学校数据负责人、最小字段、保存期限、导出审批、删除与法律保全流程 |
| 评委描述 | 活动内评委姓名与席位；活动运营数据 | 活动负责人确认展示范围、保存期限和离场后的撤销流程 |
| QR/grant/session 派生值 | 兑换、撤销、短期会话；凭据派生数据 | 只保存 digest/状态/范围/时间；禁止原始 secret/token 进入数据库、日志、导出或 trace |
| 成绩与 panel 快照 | 评分事实、来源、席位、上下文；正式业务数据 | Staff/Admin 评分与纠正授权、锁定/解锁证据、导出范围、修订保留策略 |
| 审计/IP/request 元数据 | 追责、滥用调查；安全审计数据 | 学校批准的保存期限、访问审批、时钟同步、脱敏与导出链路 |
| 私有文件 | 报名材料、演出文件、生成文档；受控文件 | 文件责任人、下载授权、备份范围、删除/法律保全和媒体恢复证据 |
| 备份/导出 | 灾难恢复与正式交付；高敏汇总数据 | 独立存储责任人、加密/访问控制、RTO/RPO、隔离恢复记录、到期销毁证据 |

## 身份、角色和高风险操作

Judge 是活动范围内的临时身份；工作人员和管理员仍是唯一的持久操作身份。未来 SSO 必须使用不可变的 `(issuer, subject)` 映射到既有账户或显式邀请，不能通过邮箱、姓名或模糊匹配授予权限。SSO 不应把 provider-specific 字段塞入 Judge 或 JudgeSeat。

学校必须在上线前书面批准以下高风险操作的 MFA 或重新认证策略：评委组变更、解锁、导出、恢复和保留期清理。未完成该批准时，系统只能标记为部署前置条件，不能宣称学校接入完成。

## 公网和基础设施边界

生产 Web 只允许通过批准的反向代理进入；TLS 证书、可信 forwarded-header 配置、WAF、连接超时、慢连接防护、连接数限制和 volumetric DDoS 由学校网络或批准的边缘平台负责。应用限流、请求体上限和会话撤销是纵深防御，不能替代边缘防护。上线前应保留配置审查、告警测试和小规模受控攻击测试证据；禁止在学校公网执行未批准的压力或攻击实验。

数据库保持私有，PostgreSQL 备份必须恢复到隔离目标并运行 Django check；恢复演练不得重置源卷。生产环境、域名、TLS、WAF 和备份目标均需由部署方提供实际证据。

## 交接结论

以下任一项缺失时，结论只能是 `HOLD`：数据责任与保存期限、SSO/MFA 决策、代理 header 信任证据、边缘防护证据、私有数据库、隔离恢复、事件联系人或纸面评分 DR 链路。应用代码门禁通过不等于学校批准接入。
