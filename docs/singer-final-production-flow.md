# 院十佳决赛生产流程

这份说明面向操作当前学年院十佳决赛的工作人员，记录从历史模板到当年正式运行的完整路径，以及各步骤背后的权威边界。工程约定见[开发基线](development-baseline.md)，现场演练场景见[生产彩排 Runbook](production-rehearsal-runbook.md)。

## 活动语义

ArtFlow 中的一次「院十佳」活动表示**院十佳决赛的完整运行实例**。它内部可以拥有多个评分轮次、比赛环节或赛段，这些轮次是决赛内部的一部分，不是海选或初赛，也不对应现实世界的前置筛选。ArtFlow 不负责海选、初赛等校外或线下前置过程。

因此后台的 `r1/r2/r3/r4` 只表示决赛内部的轮次顺序。

## 历史模板与当年赛制

模板库中的「院十佳 2025（历史模板）」是 2025 年的历史事实，用做回放、能力验证与克隆起点：

- 稳定机器身份是 `builtin_key = golden_schidui`；显示名称只是界面文字，改名不会产生第二个模板；
- 该模板的定义（含 2025 权重）保持历史原样，不会因为系统能力增强而改写；
- 系统内不硬编码任何年份的权重或轮次。

当年赛制一律在克隆之后按当年规则调整。

## 正式运行流程

1. **创建活动**：Admin 创建当年院十佳决赛活动，生命周期为 TEST。
2. **克隆**：在赛制模板库中选择「院十佳 2025（历史模板）」克隆到该活动（或用「克隆去年赛制」按钮，它按 `builtin_key` 定位模板）。
3. **调整当年规则**：维护轮次/环节（`ContestRound`）、评分表（`ScoringRubric`），以及轮次、分组、投票与观众分的绑定。
4. **配置观众票**（使用原生扫码投票时）：创建 VoteSession，用途选择「成绩组成」，并勾选入场票校验；为它配置成绩换算规则（有效票支持率）；在赛制绑定里把 `vote_source` 指向该投票与换算规则。
5. **完整彩排**（TEST）：用测试数据走完录入、投票、观众分，确认每个赛段在必要输入齐备后自动进入待核定，再逐段核定。
6. **校验并冻结**：Admin 执行赛制冻结。冻结会把绑定快照进版本，包括绑定的 VoteSession、VoteScoringRule、换算方式与结果量纲。
7. **正式化**：确认生产就绪门禁后，把活动从 TEST 提升为 FORMAL。
8. **正式运行**：现场录入 → 自动解析 → 核定 → 结果板与主持手卡。

## 观众分的两个来源

两个来源互相独立，绑定同一个 `vote_source` 会被拒绝：

### 扫码投票（原生链路）

```
VoteSession（用途=成绩组成，requires_ticket=True）
→ 有效 ballot（一票一场一份）
→ VoteScoringRule（ballot_share_percent）
→ 0-100 成绩分
→ resolver
```

- 支持率 = 该选手有效票数 ÷ 有效 ballot 总数 × 100；分母是有效 ballot 数，不是投票记录数；
- 多选时各选手支持率之和可以超过 100%，这是正确结果；
- 候选人名单必须与所评分赛段的名单一致，否则冻结时拒绝；
- 没有有效 ballot 时不产生 0 分，赛段保持待定。

### 人工/外部核验

`AudienceScore` 是人工核验后的 0-100 成绩分，用于外部表单 DR、公网不可用或事先定义的观众分兜底策略。录入前须双人核对，并在录入页保留来源说明；每次录入都会留下审计记录。

它**不是**扫码投票的自动转换结果，系统不会把 VoteSession 的数字复制进 AudienceScore。

## 报名与材料窗口

- 报名开放期间：选手可自由编辑自己的报名资料，并为自己每一个文件型材料检查项上传文件。
- 报名截止（含审核阶段）之后：报名资料与材料锁定。只有 Staff 明确标记为「需补交」的材料检查项才对选手开放上传，且上传按材料检查项提交，文件用途取自服务端维护的材料用途快照——浏览器不能指定用途。
- Staff 自己的材料管理不受此限制。

## 冻结与核定的门禁

- 成绩组成投票必须是明确的 VoteSession 用途，并且启用入场票校验；
- 原始票数（量纲为 votes）不能直接进入加权综合分；
- 赛段核定要求它消费的轮次与投票场次都已锁定；
- 已核定赛段消费过的原始数据不能就地改写，必须先由管理员解锁该赛段结果。
