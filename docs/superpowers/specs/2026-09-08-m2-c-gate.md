# M2-C-GATE Specification

## Goal

Make the completed M2-C Judge authority/client boundary a named, repeatable
repository gate. The gate must prove the local authority contract in both
SQLite and PostgreSQL CI paths, keep the complete Pyright baseline blocking,
and record the school/deployment items that code cannot prove.

## Contract

### CI enforcement

- The Linux quality job runs both `npm run check:pyright` and
  `npm run check:pyright:entry-access`.
- The PostgreSQL integration job runs the complete Judge authority focused
  suite before the broad application suite:
  `singer_contest.test_judge_authority`, `singer_contest.test_judge_http`, and
  `staff_panel.tests.JudgeControlHTTPTests`.
- A failure in either focused suite or either Pyright configuration fails the
  workflow; no `continue-on-error` or conditional bypass is allowed.
- Existing CSS, client, Playwright, security, migration, and full-suite gates
  remain unchanged and continue to apply.

### Evidence boundary

The gate records local code evidence only: authority guards, provenance,
idempotency, stale context, rubric materialization, HTTP boundaries, client
typing, PostgreSQL execution, and browser smoke. It must explicitly retain
HOLD status for real school IdP/SSO, MFA/re-authentication approval,
TLS/WAF/DDoS, data ownership/retention approval, and real credentialed event
rehearsal.

### Safety

- No workflow may publish the database service port or destroy source volumes.
- No gate may place bearer tokens, QR secrets, student PII, or complete judge
  context payloads in artifacts.
- No new ORM write path is introduced by the gate.

## Acceptance criteria

1. Workflow YAML contains the two Pyright commands and the PostgreSQL focused
   Judge command.
2. Local workflow/contract tests reject removal of those commands or accidental
   `continue-on-error` bypasses.
3. Focused SQLite and PostgreSQL runs pass locally when Docker is available.
4. Readiness documentation names the gate results and preserves deployment
   HOLDs.
5. Two security/authority review rounds find no target-trust, direct-write,
   secret-leakage, or semantic consistency regression.

## Non-goals

- No SSO provider integration.
- No claim that local tests provide WAF, DDoS mitigation, TLS, institutional
  compliance, or school approval.
- No workflow redesign unrelated to M2-C.
